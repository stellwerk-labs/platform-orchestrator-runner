# Runner 3.4.0-rc.6

This candidate changes only what the Runner image contains. Runner behaviour, configuration, dependencies and the bundled OpenTofu `1.13.9-stellwerk.remediation.20261123.1` and Infracost `v0.10.49+stellwerk.1` versions are unchanged from 3.4.0-rc.5, whose notes still describe the Pipelines candidate.

The image is about 40% smaller to download: 106 MiB instead of 175 MiB compressed for linux/arm64, and 114 MiB instead of 187 MiB for linux/amd64. Unpacked, it takes 365 MB instead of 446 MB (arm64) and 386 MB instead of 471 MB (amd64). The Runner, OpenTofu and Infracost executables no longer carry DWARF debug data. Their symbol tables remain, so binary vulnerability scanners keep symbol-level results and stack traces keep function names, files and line numbers; Runner stack traces now show module paths instead of build directory paths. `/licenses` no longer contains the `testdata/` test fixture directories that were copied with saved dependency source; no shipped executable compiles or embeds them. Licence texts, notices and the OpenTofu and Infracost corresponding-source archives remain, and each `SOURCE.json` records the new archive hashes.

Native sites upgrading from 3.4.0-rc.5 must update their execution catalogue. The catalogue digest covers the OpenTofu and Infracost executable bytes, which changed, so rc.6 workers refuse to start with `catalog_refused` until the catalogue is updated. Settle or resolve accepted executions, stop the rc.5 workers, run `rollout-catalogue-update` with the rc.5 tools digest as `--expected-catalogue`, then export and publish the new catalogue and reissue the activation record, as described in [Updating a Native execution catalogue](../native-rollout-catalogue-updates.md). Commands submitted with the rc.5 digest are refused, and saved Plans from rc.5 need a new Plan before Apply. Sites on the retained SQLite pipeline profile export the catalogue again with `runner rollout-catalogue` and publish it to Core. Installations that run no pipeline workers, including the chart's remote Job default, need no action.

The release build's binary vulnerability check now refuses an executable without a symbol table instead of scanning it imprecisely; shipped images are unaffected.
