# Runner v3.3.0

Runner adds default-on offline monthly base disk estimates to successful manual and Drift plan logs.
The initial reviewed subset prices fully known AWS GP3 EBS volumes and Azure Premium LRS/ZRS managed disks using pinned Pogi `0.2.0` catalogue snapshots dated `2026-10-20`, in USD.
Coverage counts expose partial and unpriced resources; unsupported providers, compute assumptions and the empty GCP catalogue never become silent zero-cost infrastructure.

Set `COST_ESTIMATION_ENABLED=false` in the Runner environment to opt out.
Estimation is local and adds no accounts, pricing keys, network calls or runtime downloads.
Failed estimation does not change existing plan, deployment or observation results.
Default Drift jobs emit estimates at `INFO` to job container stdout. Observations do not persist encrypted logs, so Drift estimates require operator Pod-log access or an external collector and are not available through ordinary CLI/Console deployment-log retrieval.
Estimates respect `LOG_LEVEL`; manual estimates enter stored deployment logs when an encrypted logs recipient is configured.
The image ships the separately licensed MIT source component's licence, exact original/adapted file manifest and SPDX inventory under `/licenses/pogi/`, checked by the existing production notice gates.

See [the feature documentation](../cost-estimation.md) for eligible disk configurations, omitted charges, snapshot limits, privacy and coverage semantics.
The existing deployment and observation security, queue, lease and protocol contracts continue unchanged.
