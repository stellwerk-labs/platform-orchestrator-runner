# Runner v3.3.1

Security patch release for Runner `v3.3.0`. Runner behaviour, configuration and APIs are unchanged.

The bundled classic Infracost executable advances to upstream `v0.10.51`, packaged as `v0.10.51+stellwerk.1` with the same documented OpenPGP dependency patch.
Its effective dependencies now include OpenTelemetry `v1.47.0` and the fixed `github.com/gorilla/websocket` revision, resolving GO-2026-6974 and GO-2026-6278 in that executable.
Symbol-aware scanning of both Linux Infracost executables reports no vulnerabilities.
Upstream `v0.10.50` and `v0.10.51` tighten some AWS price filters, so individual estimates can differ from `v0.10.49`.
The cost estimation contract, credentials and network boundaries are unchanged; see [cost estimation](../cost-estimation.md).

The Runner module's indirect OpenTelemetry SDK modules move to `v1.47.0`.
The Runner executable itself reports no vulnerabilities.

The bundled engine moves from official OpenTofu `1.13.2` to the newest patch release, official `1.13.10`, with unchanged signature and checksum verification.
Its dependency set is unchanged; the newer Go `1.27.4` toolchain resolves GO-2026-6859.
New state is written with tool version `1.13.10`.

The official OpenTofu `1.13.10` executables retain 14 advisory IDs and 1432
scanner finding records on each architecture, with unresolved runtime
applicability. The release owner accepted this exact residual risk for Runner
`v3.3.1` and its RCs until upstream fixes them; see the
[version-scoped disposition](vendor-residuals-v3.3.1.md).
All other security and release gates remain mandatory.
