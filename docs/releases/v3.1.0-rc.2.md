# Runner v3.1.0-rc.2

This release candidate supports managed Module Versions while preserving the
existing Terraform/OpenTofu execution path.

Compared with rc.1, the integration fixture and candidate CI triggers change: the APIs wait for IAM's
readiness and event-stream bootstrap, and Vault initialization preserves existing
transit keys on fixture restart. Candidate branch/tag pushes no longer duplicate the
full suites run by the manual release workflow. Product behavior and required
execution gates are unchanged.

## What changes

- Carry version identity and immutable source metadata through normal execution.
- Execute legacy v0 snapshots without manufacturing a digest or SemVer.
- Accept the optional external artifact-digest contract. A missing digest is
  not an integrity mismatch; inline source must not carry an external digest.
- Preserve existing state, log and output encryption and normal callback behavior.

A stored digest is a publisher's claim. This release does not introduce a trusted
artifact verifier, signatures or a canonical cross-client artifact serialization.
Do not interpret Unverified as permission to ignore normal deployment controls.

## Upgrade and operation

Use CP 3.0.0-rc.4 and DP 3.2.0-rc.4. Upgrade through the supported Runner/agent
configuration and keep referenced external source revisions available for
redeployment and recovery. Retain state-storage credentials and keys throughout
any teardown that still needs the Runner.

The standard Runner and gateway continue to use the established communication
path; there is no second infrastructure execution engine. Cross-namespace jobs
require the matching chart's namespace-qualified callback address.

This candidate tag publishes Runner artifacts, not a new agent chart release.
Use the tested agent/chart combination and verify real job dispatch, callback
handling and output access after upgrading. Stable channels remain unchanged.
